## MVP 1.1–1.2 存檔相容性

- 舊裝備 instance 沒有 `refineLevel` 時會補為 +0；不需遷移帳號版本或存檔 key。
- 精煉程度附著在裝備 instance 上，替換／卸下後仍保留；已鑲嵌卡片也會保留。
- 不重設角色、技能、能力點、Zeny、共用倉庫、圖鑑或任何過往獎勵；精煉只會扣除玩家確認的費用。

## 目前限制

- 精煉規則（+5 上限、保證成功、每階段目標等級 × 100 Zeny）及所有裝備戰鬥加成為本專案原型，未宣稱與台灣官方 PC RO 現行正式規則一致。
- 尚未實作玩家間交易、精煉材料或更多高階裝備／正式道具資料。
- 二轉／轉生、獨立角色／怪物受擊與死亡逐格素材仍待擴充。
- 地圖音樂尚未逐張依台灣官方 PC RO 對應表核實。
- 尚需進行桌面／手機瀏覽器實測及取消分頁鎖後的多分頁壓力測試。

## MVP 1.2 交易與卡片相容性

- 不更改 ro-h5-account-v1、既有角色槽、共用倉庫、Zeny、裝備 instance 或卡片堆疊結構；出售價格存在物品定義內，舊裝備沒有 cards 時視為無鑲嵌卡片。
- 取出卡片只移除指定卡槽的一張卡，並把一張卡加回共用倉庫；失敗時不會增加卡片或改動裝備。
- 出售只接受共用背包裡有效且未鑲嵌卡片的裝備 instance；檢查所有角色槽，避免售出仍由角色穿戴的裝備。出售後把基礎售價加至共用 Zeny，精煉費不返還。
- Service Worker shell cache 升至 v17；新增卡片效果移除、精煉保留、卡片返還、售價入帳、附卡保護、穿戴保護及 UI 接線回歸測試。

## MVP 1.3 道具／掉落相容性

- 沿用現有 `world-data.js` catalog 與裝備 instance 格式，不新增存檔 key、不清除玩家倉庫或角色進度。
- 新裝備只使用現有武器、鎧甲、鞋子與飾品四種位置；裝備限制透過 `requiredLevel`／`allowedJobs` 驗證，避免出現 UI 能取得但核心無法裝備的槽位。
- 新卡片使用現有 `effects` 可處理的攻擊、防禦、爆擊等加成；閃避與 Zeny 加成也已接入戰鬥公式。
- 回歸測試驗證總數、裝備欄位／職業／等級、每筆裝備或卡片掉落都對應有效 catalog ID、閃避實戰效果與擊倒 Zeny 加成。shell cache 升至 v18。
